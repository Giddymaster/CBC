Deployment walkthrough

Put the school system on a server

Renting a small Linux machine and running the whole stack on it — from an empty account to a school signing in over HTTPS.

⏱ 60–90 min first time 💳 from ~$12/mo 🧑‍💻 comfort with a terminal helps 🚀 one Ubuntu box, all in Docker
What you're actually building

One rented computer (a “VPS”) runs six pieces in Docker containers. You never install them by hand — the compose file does. Caddy sits at the front and gets you a free HTTPS certificate automatically.

caddyfront door · HTTPS · serves the app + photos
webDjango API + admin (gunicorn)
workerbackground jobs — report-card PDFs, SMS
dbPostgreSQL — every record lives here
redisthe worker's job queue
1
The machine

Rent the server

A VPS is a small computer you rent by the month. Any of these work — they’re all just an Ubuntu box after you’ve got it. Pick one and make an account.

The steps below use DigitalOcean because it’s the smoothest for a first deploy. If serving schools with the least lag matters more, use Lightsail and pick the Cape Town region — everything after Part 1 is identical.

Create the machine (DigitalOcean)

  1. Sign up, then Create → Droplet.
  2. Image: Ubuntu 24.04 LTS.
  3. Region: Frankfurt (FRA1) — nearest to Kenya on DigitalOcean.
  4. Size: Basic → Regular SSD → 2 GB RAM / 1 CPU (about $12/mo). The 1 GB size is tempting but the app build can run out of memory on it.
  5. Authentication: choose SSH Key (below) if you can; otherwise Password, and DigitalOcean emails you a root password.
  6. Give it a hostname like cbc-prod and click Create.
!
Set up an SSH key — it's worth the two minutes

On your own laptop, run ssh-keygen -t ed25519 (press Enter through the prompts), then paste the contents of ~/.ssh/id_ed25519.pub into DigitalOcean’s “New SSH Key” box. It’s safer than a password and you won’t be typing one every time.

When it finishes, copy the droplet’s public IP address — the four numbers like 203.0.113.42. You’ll use it everywhere below as YOUR_IP.

2
First login

Get in and set the basics

From your laptop’s terminal, connect to the box:

your laptop
$ ssh root@YOUR_IP

Say yes to the fingerprint prompt the first time. Everything from here runs on the server. Bring it up to date:

on the server
# apt update && apt upgrade -y

Add swap — cheap insurance for the build

A 2 GB box can run short of memory while building the frontend. A swap file prevents that from killing the build. Do it once:

on the server
# fallocate -l 2G /swapfile
# chmod 600 /swapfile
# mkswap /swapfile
# swapon /swapfile
# echo '/swapfile none swap sw 0 0' >> /etc/fstab

Turn on the firewall

Allow SSH so you don’t lock yourself out, then enable it. Docker opens ports 80 and 443 itself, so you don’t add those here.

on the server
# ufw allow OpenSSH
# ufw --force enable
3
The one dependency

Install Docker

Docker runs all six pieces. The official one-liner installs it and the compose plugin together:

on the server
# curl -fsSL https://get.docker.com | sh
✓
Check it landed

docker --version and docker compose version should each print a version number. If both do, you’re set.

4
The app + its settings

Get the code and configure it

Clone the repository and step into it:

on the server
# git clone https://github.com/Giddymaster/CBC.git
# cd CBC

Copy the settings template and generate a secret key (paste the output into the file in a moment):

on the server
# cp deploy/.env.prod.example deploy/.env.prod
# python3 -c "import secrets; print(secrets.token_urlsafe(64))"
# copy the long line it prints
# nano deploy/.env.prod

For the first run we test on the IP over plain HTTP — no domain needed yet. Set these values (leave the M-Pesa / SMS keys blank for now):

SettingValue for the IP smoke test
SECRET_KEYthe long line you just generated
SITE_ADDRESS:80
SECURE_SSL_REDIRECTfalse
ALLOWED_HOSTSYOUR_IP
CORS_ALLOWED_ORIGINShttp://YOUR_IP
POSTGRES_PASSWORDany strong password you invent

In nano, save with Ctrl-O, Enter and exit with Ctrl-X.

5
Lift-off

First boot

The command to drive the stack is long, so make a shortcut for this session:

on the server
# alias dc='docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.prod'

Now build and start everything. The first time downloads images and builds the app, so give it a few minutes:

on the server
# dc up -d --build

Create the database tables, then create your operator account:

on the server
# dc run --rm web python manage.py migrate
# dc run --rm web python manage.py createsuperuser
!
This superuser is you — the platform owner

It asks for a username, email and password. It won’t ask for a school, and that’s the point: a superuser with no school is the operator, sitting above every school. Keep these credentials safe.

✓
See it running

dc ps should list all five services as running. Open http://YOUR_IP in a browser — you should get the sign-in screen. Log in with the operator account and you’ll land on the Operator Console.

6
A real address, with a padlock

Point a domain and turn on HTTPS

Buy a domain from any registrar — Namecheap or Cloudflare are simple; a Kenyan .co.ke comes from a local registrar like Truehost or KENIC. Then, in that registrar’s DNS settings, add one record:

TypeName / HostValueTTL
A@  (or app for a subdomain)YOUR_IPAutomatic

DNS can take a few minutes to an hour to spread. When yourdomain.com resolves to your IP, edit the settings again to switch on the real address and HTTPS:

on the server
# nano deploy/.env.prod
SettingNew value
SITE_ADDRESSyourdomain.com
ALLOWED_HOSTSyourdomain.com
CORS_ALLOWED_ORIGINShttps://yourdomain.com
SECURE_SSL_REDIRECTtrue

Recreate the containers so they pick up the new settings:

on the server
# dc up -d
!
Using Cloudflare for DNS?

Set the record to “DNS only” (grey cloud, not orange) for this setup, so Caddy can fetch its own certificate. You can turn the proxy on later once you understand the trade-offs.

✓
The padlock

Give Caddy up to a minute, then open https://yourdomain.com. You should see a valid certificate (the padlock) and the sign-in screen. If it doesn’t appear, check dc logs caddy — it prints exactly what the certificate step is waiting on.

7
Your first customer

Register a school

Sign in as the operator, open the Register tab in the console, and fill in the school’s name, code, county, and the first admin’s name. The system creates the school, its admin login, and a free trial in one step, and shows you the admin’s password once — hand it to the school.

×
Don't seed demo data on a real server

The seed_demo and seed_curriculum commands are for exploring locally. On the machine your real schools use, only ever create schools through the console.

8
Before anyone real relies on it

Set up backups

Everything that matters lives in two Docker volumes: cbc_pgdata (the database) and cbc_media (learner photos and report cards). Back both up and copy them somewhere else. This is a register of children’s records — losing it is not an option, and the Data Protection Act obliges you to protect it.

on the server
# database → a compressed dump
# dc exec -T db pg_dump -U cbc cbc | gzip > cbc-$(date +%F).sql.gz

# photos + PDFs → a tarball
# docker run --rm -v cbc_media:/m -v "$PWD":/out alpine \
      tar czf /out/media-$(date +%F).tar.gz -C /m .

Put those two lines in a daily cron job and push the files to object storage or another machine. Then test a restore once — a backup you’ve never restored is a guess, not a backup.

Updating later

When there’s a new release, from inside CBC:

When the first boot misbehaves

Common snags

A first deploy almost always hits one or two of these. None are serious.

The build gets “Killed” partway through

Out of memory. Add the swap file from Part 2 if you skipped it, or resize the droplet to 2 GB, then run dc up -d --build again.

The page says “Bad Request (400)”

The address you’re visiting isn’t in ALLOWED_HOSTS. If you’re on the IP it must list YOUR_IP; on a domain it must list the domain. Fix the env file and dc up -d.

HTTPS never gets a certificate

Caddy needs the domain pointing at the box and port 80 reachable. Confirm DNS has propagated, and if you use Cloudflare set the record to “DNS only” (grey). dc logs caddy shows what it’s stuck on.

The site loads but shows an error / 502

Usually migrations haven’t run, or the database is still starting. Run dc run --rm web python manage.py migrate, then dc logs web to read the actual message.

I edited the env file but nothing changed

Containers read settings at start. After any change to deploy/.env.prod, run dc up -d to recreate them.

I can’t SSH in at all

Check the provider’s own firewall/networking page allows your SSH port, and that you’re using the right key or the emailed password.
